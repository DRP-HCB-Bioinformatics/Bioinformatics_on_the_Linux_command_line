Working with Files

Viewing

So far, we have only worked with empty files and haven’t looked at the content of files. There are several core ways to look at the content of a file. First, lets move into the folder below.

cd ~/Intro_to_Linux/yeast_files/

The first file we will take a look at is a BED file. This file contains information on genes located on a reference genome, with each line representing a unique gene. This is a standard text file format used in bioinformatics. There are several ways to look at the content of text files. The first is head, which will print the first few lines of the file to the terminal.

head yeast_genes.bed

Similarl to looking at the start of the file, there is a command for looking at the end of a file, the command tail will return the last few lines of the file.

tail yeast_genes.bed

Both of these can be very useful to be able to peek at files, especially when they are really large. To look at the full file, the cat command can be used to print the whole file to the terminal.

cat yeast_genes.bed

For large files, the content will whizz past, too fast to read. To be able to scroll through the content of files easily the command less is useful.

less yeast_genes.bed

You can scroll through the BED file one line at a time using the [Down Arrow] and the [Up Arrow] keys. You can also use the [Page Down] or [Space] and [Page Up] or [B] keys to scroll through the file one page at a time. To access the help, use the [H] key and finally to exit the file, use the [Q] key.

Challenge 1:

Take a look at the --help for head. Print the first 5 lines of the BED file.

Solution

Solution.

Solution:

First, lets look at the help for head.

head --help

From the results, we can see that -n can be used to print a specific number of lines.

head -n 5 yeast_genes.bed

Another very useful command is wc (word count). This command will report the number of lines, words and bytes within the file.

wc yeast_genes.bed

Often it will be used to look at the number of lines within the file. To only get the line count, add the -l option.

wc -l yeast_genes.bed

Searching

In many cases, looking at the full file might not be useful. A way to search for specific text is using grep. For example, we can look for specific genes in our annotation file.

grep "YAL040" yeast_genes.bed

Key points

The grep command has a lot of different options, an overview of the most important options can be found below.

  • -i will make the search case insensitive
  • -v will report all lines that do not match the searched term
  • -c will count the lines with a match

There is also the option to use regular expressions within grep. If you have never heard of regular expressions, these are expressions that will help search for patterns instead of fixed text. Some characters can be used to search for patterns.

  • ^ represents the start of a line
  • $ represents the end of a line

More complex regular expressions can be used in grep with the options -E and -P.

  • \t represents a tab
  • \n represents an enter (or new line)
  • . matches any single character
  • * represents zero or more occurrences of the character before the *
  • + represents one or more occurrences of the character before the +

Binary files

Binary files are non human readable files. These files are specifically for computers to read. This includes zip files. Generally, they are compressed to take up less space, which is great for large bioinformatics files. In the yeast folder, there is an example of a compressed file. The file is gzipped, which is a different form of zip file. FASTQ files are commonly gzipped. These files contain DNA sequence information from sequencing platforms. The files contain headers, sequences and quality information for each sequencing read. We will look more in depth into them later on, but for now we will focus on compression.

head raw_yeast_rnaseq_data.fastq.gz

Clearly not human readable. Sometimes we need to get information from these files without wanting to unpack them on the server. Linux has a number of commands that will work on compressed files. Similar to the commands we used previously, we can use zless, zcat and zgrep on compressed files.

Challenge 1:

Extract all lines starting with an @ symbol from raw_yeast_rnaseq_data.fastq.gz and count the number of lines.

Solution

Solution.

Solution:

First, lets get all the lines that start with an @ symbol. Because this is a binary file, we need to use zgrep. Remember that we want lines that start with the symbol, so we need to use ^

zgrep "^@" raw_yeast_rnaseq_data.fastq.gz

To get the count of lines that match this, we can use the -c option for zgrep.

zgrep -c "^@" raw_yeast_rnaseq_data.fastq.gz

Zipping and Unzipping

Even though compressed files use less disk space, in some cases we want to unpack them. There are 3 main types of compression files that need different ways of unpacking: zip, gzip and tar.

  • unzip can unpack zipped files, zip can create zips. Zips can contains single files or complete folders.
  • gunzip can unpack gzipped files and gzip created gzipped files. Generally gzip is used for single files.
  • tar can be used to unpack and create tar files. Tar is used for folders and often another form of compressing is used on top of it. You will often find tar.gz files.

The two main compression types found using Linux are gzip and tar. Lets look at an example for both.

gunzip raw_yeast_rnaseq_data.fastq.gz

Challenge 3:

Navigate back to the Intro_to_Linux folder, what is the name of the file which ends in tar.gz.

Solution

Solution.

Solution:

Use cd to move back to the Intro_to_Linux folder. Use ls to see an overview of the content.

cd ~/Intro_to_Linux

ls

There is a file in the folder named tar-latest.tar.gz.

To unpack the file, we can use tar. Several options are needed to unpack the file.

  • -x specifies that files need to be extracted.
  • -v reports what the command is doing (verbose).
  • -a automatically handles decompression (gunzip in this case)
  • -f (which needs to be at the end) specifies the tar file to unpack.

As you can see below, we can add all the options together into a single combination for the tar command. The command is the following:

tar -xvaf tar-latest.tar.gz

This will take a couple of minutes, if it is confusing to add options together, the previous is the same as the following:

tar -x -v -a -f tar-latest.tar.gz

As the file is unpacked, a list of files and folders is written to the terminal. We can double check that a folder named tar-1.35 has been created within the current folder using ls.
