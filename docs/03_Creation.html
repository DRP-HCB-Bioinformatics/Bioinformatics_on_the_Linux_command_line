Creating Files

Make, Move, Delete

To be able to work within Linux, we need to learn to make, move and delete folders and files. To start, lets make sure that we start in the Intro_to_Linux folder.

cd ~/Intro_to_Linux/

First, we will take a look at creating directories. For this we can use the mkdir (make directory) command. Let’s start by creating two folders, temp1 and temp2

mkdir temp1 temp2

As you can see, we can create two folders in one go. The mkdir command can take multiple names and will create all the names separated by a space in the current directory, unless specifically told to make it somewhere else. Lets check if the directories have indeed been created.

ls

Files can be copied to other directories using the cp (copy) command.

Files can be moved using the mv (move) command. Similar to the copy command it takes the file which is to be moved and the location to which it should be moved.

mv myfile2.txt ~/Intro_to_Linux/temp2/

Move can also be used to rename files, for that we give it the current name and the name it should be renamed to.

And of course double check if the file has correctly been renamed.

NOTE: Use the mv command with caution. Linux does not check if the filename you are moving to already exists. Any existing files will be overwritten. The -i option to mv provides an interactive version of move which asks before overwriting existing files.

Go back to the Intro_to_Linux directory:

cd ~/Intro_to_Linux

The last thing to look at in this chapter is how to remove files and folders. Both can be deleted using the rm command, however for folders an option needs to be added. To remove files, we can do the following.

rm temp1/myfile1_renamed.txt

If the same thing is done for a folder, an error is reported.

rm temp1

Because it is a folder, rm needs to know that we are okay with removing a folder and everything that is inside of it. Even if the folder is empty, rm needs confirmation.

rm -r temp1

Key points

Linux doesn’t always reply to commands. For Linux, no news is good news. If we do not get any reply from Linux after running a command, this means that the previous command has been done and there is nothing to report. If we want to make sure commands are run correctly, we need to do checks ourselves.

In some cases, the option -v can be added to commands to have a verbose output which reports what the command is doing.

Challenge 4:

Remove folder temp2. Make sure to use the -v option while removing the folder.

Solution

Solution.

Solution:

We have to combine multiple options for this.

Warning

Whenever you remove or overwrite files from the command line, they are gone. Forever. There is no Trash or Recycle Bin like within a graphical environment. There is no easy way to get them back!

Some servers have daily backups, however this is not something to depend on. Make sure you have backups of important data.

One tip is to always do an ls of the folder you want to remove before actually deleting it. This way you can make sure you are removing the correct folder and are aware of what is inside the folder. You can also use the -i interactive option, this will ask you to confirm everything it removes. Be very aware of typos and spaces in your commands!

## EXAMPLE - DO NOT RUN
#rm -r ~/Project /temp2

Instead of removing ~/Project/temp2 folder, the command above will attempt to remove the full Project folder and temp2 in the root folder, because of the space in the directory name. This could be catastrophic.

Permissions

So far, we have worked within our home directories on the server. By default, this folder is owned by you. When we want to share files and folders with other users, we can change ownership of files or change permissions to allow others to access.

Each file (and directory) has three sets of permissions:

  • user: Permissions for a user that owns the file or directory
  • group: Permissions for a user group associated with the file or directory. A user may belong to several groups but a file or directory only has one group.
  • others: Permissions for anyone else that is not the owner or part of the associated group.

Each file and directory also has three basic permission settings:

  • read (r): Ability to read the content of a file or directory.
  • write (w): Ability to write or edit a file or directory.
  • execute (x): Ability to run the file as a program. For a directory, this is the ability to go into the directory and access files inside.

For a directory with only execute permissions, you can read the contents but only if you already know the names of the files. You cannot list the files without the read permission on a directory. This is rarely useful, generally on any directory you want to set read and execute permissions both on, or both off.

To take a look at this, lets create a file again.

touch myfile.txt

To get information on permissions, we can use the ls command again. To list permissions, the option -l needs to be used.

ls -l myfile.txt

The first column (-rw-r–r–) contains the permissions.

  • The - at the start indicates that this is a file. If it was a d, it would be a directory. If it was an l it would be a link (we will talk about links later on).
  • The next 3 characters are user permissions. rw- means that the user can read the file (r), can write to and edit the file (w), but cannot execute the file (-).
  • The next 3 letters are group permissions. r-- means that the group can read the file but cannot edit or execute the file.
  • The last 3 characters are others permissions. Again we see r--, which means others can see the file but make no changes or execute the file.

Challenge 5:

Look at the permissions for all the files in the Intro_to_Linux folder. Identify different permissions over the different files.

Solution

Solution.

Solution:

First we have to list the details for all the files and directories using ls

ls -l

To change permissions of files, the chmod (change mode) command can be used.

  • The chmod command uses the letters u, g and o to represent user, group and others.
  • To change permissions for everyone you can use a for all.
  • The chmod command uses the letters r, w and x to represent read, write and execute.

For example, to stop other users on the system from accessing myfile.txt, we can remove the permissions for group and others:

chmod g-r myfile.txt

chmod o-r myfile.txt

ls -l myfile.txt

If we want to add permissions, use a + instead of a -.

Setting permissions recursively (directory and all files inside of it) is possible, for this the -R option can be used. The command below is a very handy command. It means “make my current directory and everything inside of it readable and writable by me”. Note the uppercase X properly sets the directory permissions, remembering that we want both read and execute set on directories. If we used a lowercase x it would also make all the files executable, which we probably don’t want.

chmod -R u+rwX .

File permissions can be confusing, here is a useful tool to help.

Symbolic links

Sometimes, we want to easily access a file in another directory without copying it into our working directory. Symbolic links, also known as soft links or symlinks, are pseudo-files that link to another file or directory (similar to a shortcut in Windows). In bioinformatics, these links are often used to reduce duplication of large data files or reference genomes.

Symbolic links are created using the ln (link) command with option -s. The -r option makes the command behave more nicely, similar to the cp or mv command.

ln -sr ~/Intro_to_Linux/genomes/human/hg38/genome.fa ./
